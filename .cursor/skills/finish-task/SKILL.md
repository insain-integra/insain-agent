# Завершение принятой задачи

Кто выполняет шаг — роль из docs/agents/roles/. Skill описывает действия, не подменяет роль и не выбирает модель. Выполняет агент по команде человека; решение «принято» уже принято человеком или Reviewer, skill его не выносит.

Правила, которые skill не отменяет (`AGENTS.md`): пуш — только с подтверждения человека; удаление веток — тоже; деплой только с зелёного CI.

`<имя>` — имя файла задачи без `.md`. Ветка — `task/<имя>`, её worktree — `..\insain-agent-<имя>` (`git worktree list`).
Чат — в основной папке на `main`: шаги 1–5 идут в worktree задачи, шаги 6–12 — в основной папке.
Ветки нет (быстрый режим, прод без git, закрытие после выкатки) — всё в основной папке, шаги 4–6 пропустить.
Таблица «кто и когда» — `docs/agents/workflow.md`, «Слияние и закрытие».

## Можно ли завершать

1. Статус и журнал:

   ```powershell
   Select-String -Path todo\<имя>.md -Pattern "^Статус:|— Reviewer, .* — принято|— человек — принято"
   ```

   Ожидается: статус `ревью` или `закрытие` и строка «принято» от Reviewer (или от человека, если в шапке `Reviewer: не нужен`).
   Иначе — стоп: задача не принята, сказать человеку, чего не хватает.

2. Прод после слияния. В смешанной цепочке (`docs/agents/workflow.md`, «Цепочки») выкатка идёт после merge: если в «Scope» есть шаги Site ops на боевом сайте, которые ещё не сделаны, задача не закрывается. Выполнить шаги 3–7 (в шаге 3 статус — `выкатка`), закоммитить, шаги 10–12 (пуш, CI, удаление worktree и ветки), дать промпт Site ops и остановиться. После отчёта Site ops со статусом `закрытие` — второй запуск: шаги 1, 3, 7–12. Задача на копию формы ezFC боевую форму не трогает — её закрывать можно.

## Приёмка и коммит на ветке

3. В «Журнал передач» строка человека и статус:

   ```text
   - ДД.ММ.ГГГГ — человек — принято — закрытие
   ```

   `Статус: закрытие`. В «Результат» заполнены «Было / стало» и «Ветка, PR или коммит» — без них `close` откажет. Не выдумывать: пусто — спросить человека.

4. Дерево ветки:

   ```powershell
   git branch --show-current; git status --short
   ```

   Ожидается: `task/<имя>`, в списке только файлы из «Файлы» задачи, `docs/dashboard.md` и `todo/<имя>.md`. Чужие файлы — не коммитить, спросить человека.

5. Коммит одной осмысленной правкой (английский, по смыслу, как в `git log`):

   ```powershell
   git add <файлы задачи>; git commit -m "<что сделано>"
   ```

## Слияние

6. Fast-forward в `main` — в основной папке. Сначала diff ветки — только файлы задачи; закрытый в `main` файл `todo/` в списке (вернулся после rebase) — убрать из ветки с подтверждения человека:

   ```powershell
   git branch --show-current; git diff --stat main...task/<имя>
   git pull --ff-only; git merge --ff-only task/<имя>
   ```

   Ожидается: `main`. Основная папка на другой ветке — стоп, ветки в ней не переключать: `main` открыт в папке из `git worktree list`, шаги 6–9 там.

   Не fast-forward — в worktree задачи `git rebase main`, затем шаг 6 заново. Конфликт — стоп, `заблокировано: исполнитель`, промпт Implementer.

7. Проверка на `main`:

   ```powershell
   python scripts/dev.py check
   ```

   Ожидается: код 0, `passed` в обеих сюитах. `check` пересобирает `docs/dashboard.md` — если он изменился, добавить в коммит шага 9.

## Закрытие

8. Закрыть задачу:

   ```powershell
   python scripts/dev.py close <имя>
   ```

   Ожидается: `закрыто: <имя>.md`, `журнал и дашборд обновлены`. Строки «снят «ждёт»» и «ссылки помечены закрытыми» — перечислить в отчёте. `close` правит только `main`: задача, которая ждёт эту и живёт в своей ветке со статусом `заблокировано: ждёт todo/<имя>.md`, разблокируется в ветке руками — статус `черновик` и строка человека в журнал. Отказ — заполнить названное поле (шаг 3) и повторить.

9. Проверить запись и закоммитить:

   ```powershell
   Select-String -Path docs\history\log.md -Pattern "— <имя>$" -Context 0,4
   git add -A todo docs BACKLOG.md; git status --short; git commit -m "Close <имя>: <итог одной фразой>."
   ```

   Ожидается в журнале: период и часы правдоподобны (часы — единицы, не сотни). Иначе — не коммитить, разобраться в `scripts/close_task.py`.
   Устаревший текст эпика вокруг помеченной ссылки («ревью», «после принятия …») поправить руками в том же коммите.

## Пуш

10. Один вопрос человеку: «Пушить `main` (коммиты …) и удалить worktree `..\insain-agent-<имя>` и ветку `task/<имя>` локально и на origin?» Без «да» — остановиться, коммиты остаются локально.

11. После «да»:

    ```powershell
    git push origin main; git worktree remove ..\insain-agent-<имя>; git branch -d task/<имя>; git push origin --delete task/<имя>
    ```

    Ветки и worktree уже нет (второй запуск, задача без ветки) — только `git push origin main`. Ветки на origin нет — ошибку `remote ref does not exist` игнорировать. `worktree remove` отказал (в папке незакоммиченные файлы) — показать человеку `git status --short` той папки, `--force` не применять.

12. CI по пушнутому коммиту (`gh` нет, публичный API):

    ```powershell
    Invoke-RestMethod "https://api.github.com/repos/insain-integra/insain-agent/actions/runs?branch=main&per_page=1" | ForEach-Object { $r = $_.workflow_runs[0]; "$($r.head_sha.Substring(0,7)) $($r.status) $($r.conclusion)" }
    ```

    Ожидается: SHA пушнутого коммита, `completed success`. `in_progress` — подождать и повторить. `failure` — сказать человеку сразу: деплой с `main` запрещён до починки.

## Отчёт

Коммиты (SHA), запись журнала (период, часы), что разблокировано, результат CI. Дальше — промпт следующей задачи эпика или одна фраза, что сделать человеку.
