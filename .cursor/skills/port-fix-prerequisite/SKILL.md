# Расхождение порта с JS — задача-предпосылка

Кто выполняет шаг — роль из docs/agents/roles/. Skill описывает действия, не подменяет роль и не выбирает модель.

Обозначения: `<task>` — задача, которую держит расхождение (например `form-<slug>`), `<fix>` — задача-предпосылка, `<calcX>` — JS-функция, `<slug>` — калькулятор API. Команды раннера — `docs/js-runner-cases.md`; в PowerShell 5.1 кавычки JSON внутри `--args` экранируются `\"`.

Правило: калькулятор и `calc_service/data/` в `<task>` не правятся. Починка — всегда отдельной задачей `<fix>` со своим ревью и деплоем, даже если правка в одну строку: она меняет цены у всех вызывающих калькуляторов.

## Локализация (Implementer `<task>`)

1. Расхождение на одном входе. Раннер и боевой API, тело из `REF_*` теста (skill `ezfc-form-to-api`, шаг 3). Записать `cost`, `price`, `time_hours`, `time_ready` обеих сторон и разницу.

2. Матрица опций. Тот же вход, опции включаются по одной: без опции, опция на одном слое или ряду, на другом, на обоих. Ожидается: строка, на которой разница появляется. Совпадает при одной опции и расходится при повторе — подозрение на сброс режима или срока при повторном вызове (`mode_* = 0` после первого вызова в JS).

3. Вложенный вызов напрямую. Функцию, на которой разница появилась (`calcUVPrint`, `calcLaser` …), раннером и Python-калькулятором на одном входе, с тем режимом, который ей передаёт внешний калькулятор (часто `mode 0` у второго вызова). Ожидается: вложенный уровень расходится — баг в нём; сходится — во внешнем калькуляторе (сбор `time_ready`, ключи опций camelCase против snake_case).

4. Строка кода в JS и в Python, которая даёт разницу, с номерами строк. Типичные места: `max(1, mode.value)` вместо `* mode`; `max(time_ready …)` до проверки `mode > 0`; поле JSON, которое загрузчик не читает (`timePrepareAround`); ключ опции, который не доходит до вложенного калькулятора (`isGraveFill`).

5. Блокер по формату `docs/agents/workflow.md`: числа шагов 1–3, строка из шага 4, гипотеза, вопрос «предпосылка или расширить scope». Статус `<task>` — `заблокировано: аналитик`. Копию формы и плагин не трогать.

Перед остановкой — работа ветки в коммит, не в stash:

```powershell
git add <файлы задачи>; git commit -m "<task>: WIP до <fix>"
```

`git stash -u` не использовать: он уносит и файлы `todo/`, а незакоммиченный эталон теряется при смене ветки. Коммит — по просьбе человека; без неё — перечислить незакоммиченные файлы в отчёте и не переключать ветку.

## Задача-предпосылка (Analyst)

6. `todo/<fix>.md` по `todo/_template.md`, на `main`, не на ветке `<task>`: файл предпосылки коммитится в `main` до worktree ([workflow.md](../../../docs/agents/workflow.md), «Ветки и папки»). Статус `<task>` — `заблокировано: ждёт todo/<fix>.md` (в worktree `<task>`, если он есть). После `close` `<fix>` «ждёт» в worktree снимают руками: rebase на `main`, `черновик`, строка в журнал.

### Быстрый путь (тот же класс, что закрытый образец)

Если блокер указывает закрытую соседнюю задачу того же класса (пример: нет `size_mm` в `materials`, образец `pennant-materials-size-mm` / `flag-materials-size-mm`) — не раздувать до «средней» смешанной с нуля:

- сложность `низкая`; в «Контекст» — ссылка на образец и что копировать;
- `Reviewer: Auto` (ответ API меняется — `не нужен` не ставить);
- `Site ops: Grok 4.7`, на проде только skill `deploy-api` и smoke на входе блокера `<task>`;
- scope: та же правка по образцу + тесты на размеры и неизменность `price`; без расширения на другие калькуляторы.

Иначе — полная предпосылка ниже.

7. В `<fix>`:
   - «Контекст» — строки JS и Python из шага 4 и числа блокера;
   - «Файлы» — калькулятор, загрузчик или справочник, если правка их задевает, тест, `docs/js-runner-cases.md`;
   - «Не-scope» — такой же шаблон в других калькуляторах (не сверялись с JS), правка `<task>`;
   - критерии: эталоны раннера, падение без правки, соседи, боевой API после деплоя на входе `<task>`;
   - «Риски» — какие цены и сроки сдвинутся на проде и у каких принятых копий форм.

   Сразу проверить по шагу 4 соседние расхождения той же функции — второй круг (срок после цены) дороже, чем одна задача на оба.

## Починка (Implementer `<fix>`)

8. Эталоны — только с раннера: один на входе, который расходился, и по одному на каждую ветку правки. Пометка `# JS, ДД.ММ.ГГГГ`, команда раннера рядом и строкой в `docs/js-runner-cases.md`, assert `cost`, `price`, `time_ready` с `rel=0.001`.

9. Тест падает без правки — откатить только файл калькулятора:

   ```powershell
   git stash push -- calc_service/calculators/<slug>.py
   python -m pytest calc_service/tests/test_calculators/test_<slug>.py -q
   git stash pop
   ```

   Ожидается: новые кейсы `failed` с числами старого кода, старые эталоны `passed`. После `pop` — снова `passed`. Числа — в отчёт.

10. Соседи не сдвинулись: тесты всех калькуляторов, которые вызывают правленый (`Select-String -Path calc_service\calculators\*.py -Pattern '<Модуль>Calculator|<slug>'`). Ожидается: `passed`. Упал эталон соседа — стоп, `заблокировано: аналитик`: сосед сверялся с JS на другом режиме, переснимать его в `<fix>` нельзя.

11. `python scripts/dev.py check` — код 0. Статус `ревью`.

## Деплой и возврат (Site ops, человек)

12. После ревью и слияния в `main` — зелёный CI, `bash infra/deploy.sh`, затем боевой API на входе блокера `<task>` (тело из теста, skill `ezfc-form-to-api`, шаг 3). Ожидается: `price` и `time_ready` равны раннеру.

13. Закрытие `<fix>` — skill `finish-task`. `close` ставит `<task>` статус `черновик`. Дальше Implementer `<task>`: `git rebase main` (конфликт в тесте — брать `main`, там эталоны `<fix>`), кейс дефолта формы, затем Site ops — перепрогон копии.
