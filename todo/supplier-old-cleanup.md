# supplier-old-cleanup

Статус: черновик
Сложность: высокая
Implementer: не нужен
Reviewer: Grok 4.7
Site ops: Opus 5.5
Почему: прод, массовое удаление товаров WooCommerce и редиректы; ошибка задевает свои товары Инсайна и поисковый трафик.
Чат: человек открывает новый чат Site ops с моделью из поля Site ops; каждый шаг удаления — с подтверждения человека.

## Цель

На https://insain.ru нет карточек Проекта 111 (SKU `prg…`, 694 товара и 12 670 вариаций, 2022 год) и дубля `dbprg4594/18`. Старые адреса карточек отдают 301 на живую страницу, а не 404. Свои товары Инсайна (SKU `INS…`, 64 шт.) и калькуляторы не тронуты. Пустые рубрики одежды не висят в меню пустыми.

- `docs/site/content-inventory.md` — «Каталог поставщиков» (рубрики, числа), «Плагин insainParse». Прочитать до действий — правило `AGENTS.md`.
- `.cursor/rules/insain-site-autonomous.mdc` — целиком до первого действия на сервере.

- Остальное не открывать.

## Scope

1. Только чтение: список ID товаров `prg` и `dbprg`, их вариаций и вложений (картинок), рубрики, пункты меню; адреса карточек для редиректов. Числа — в «Результат», полный список — файлом в `/tmp` на VDS, не в git.
2. С человеком — куда ведут 301 (страница «Сувенирная продукция» или иная) и что с 13 пустыми рубриками одежды: скрыть из меню, оставить пустыми до новой загрузки или удалить. Решение — в «Результат».
3. С человеком — способ 301: Yoast на сайте бесплатный (`wordpress-seo`), редиректов в нём нет. Варианты: правила в nginx (конфиг в `infra/`, `nginx -t` и reload) или плагин редиректов (установка — с подтверждения).
4. Бэкап: `sudo -u www-data wp db export /tmp/insain-db-before-supplier-cleanup.sql --path=/var/www/insain.ru`; плюс список адресов карточек.
5. После «да» человека — сначала 301, затем удаление пачками (`wp post delete --force` по ID товаров и вариаций). Картинки — по решению человека: удалить вложения, на которые больше никто не ссылается, или оставить.
6. Пустые рубрики и меню — по решению из п. 2.
7. Плагин insainParse не выключать: деактивация удаляет его таблицы, они нужны `todo/supplier-parser.md`.

## Критерии приёмки

Команды на VDS через `ssh insain-prod`; таблицы с префиксом `wp_insain_`.

- [ ] Товаров `prg`/`dbprg` нет: `sudo -u www-data wp db query --skip-column-names "SELECT COUNT(*) FROM wp_insain_posts p JOIN wp_insain_postmeta m ON m.post_id=p.ID AND m.meta_key='_sku' WHERE p.post_type IN ('product','product_variation') AND (m.meta_value LIKE 'prg%' OR m.meta_value LIKE 'dbp%')" --path=/var/www/insain.ru` — `0`.
- [ ] Свои товары на месте: тот же запрос с `LIKE 'INS%'` и `post_type='product'` — `64`.
- [ ] Бэкап есть: `ls -la /tmp/insain-db-before-supplier-cleanup.sql` — файл ненулевого размера; путь — в «Результат».
- [ ] 301: три старых адреса карточек из списка п. 1 — `curl.exe -sS -o NUL -w "%{http_code} %{redirect_url}" <адрес>` даёт `301` и адрес из решения п. 2.
- [ ] Витрина: https://insain.ru/ и страница «Сувенирная продукция» — `200`; пункты меню рубрик одежды по решению п. 2.
- [ ] Калькуляторы живы: `curl -fsS https://insain.ru/api/v1/calculators | head -c 100`; страница калькулятора плакеток — `200`.
