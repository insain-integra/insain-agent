Статус: черновик
Сложность: высокая
Implementer: Opus 5.5

Почему: новый модуль на два контура (код в git и WordPress на проде), наценка — правило цен, перенос данных старого плагина.
Чат: сначала сессия Implementer на архитектуру (п. 1–2), затем код; выкладка — Site ops после слияния.

## Цель

Парсер поставщиков лежит в git, проходит тесты в `make check`, выкладывается на прод из `main` и по расписанию обновляет каталог, цены и остатки Проекта 111 (gifts.ru), Happygifts и Oasis. Розничная цена = цена поставщика с наценкой из JSON в git. Старый insainParse больше не нужен.

## Scope

В git (Implementer):

1. Записка-решение в «Результат» (до кода): где живёт парсер — отдельный WP-плагин в репозитории (PHP, WP-Cron, WooCommerce API) или Python-сервис на VDS (WooCommerce REST, cron), как передаются ключи (вне git), где наценка (`calc_service/data/common.json` или отдельный JSON) и как парсер её читает. Выбор — человек.
2. Сопоставление старого и нового: какие поля старый плагин писал в товар (SKU-префикс, атрибуты, рубрики), что сохраняется, чтобы новые карточки встали в те же рубрики.
3. Код парсера по решению п. 1: три поставщика, полная загрузка и обновление цен и остатков, идемпотентный повтор (повторный запуск не плодит дубли), лог запусков.
4. Наценка — в JSON в git по поставщику, по правилу `get_margin`/`MARGIN_MIN` или его аналогу для парсера; захардкоженных чисел нет.
5. Тесты на разбор фидов каждого поставщика (фикстуры — урезанные реальные выгрузки без ключей), на расчёт розничной цены, на идемпотентность.

На проде (Site ops), после слияния:

6. Выкладка, ключи поставщиков — в настройки на сервере, не в git. Расписание (WP-Cron или cron на VDS). Пробный прогон на одном поставщике в режиме «без записи» или на черновиках.
7. insainParse не выключать до решения человека: деактивация удаляет его таблицы.

## Критерии приёмки

- [ ] Решение по п. 1 записано в «Результат» и подтверждено человеком (дата).
- [ ] `make check` — зелёный, тесты парсера входят в прогон: `python -m pytest <каталог тестов парсера> -q` — `passed`, `failed` нет.
- [ ] Наценки нет в коде: `rg -n "margin|наценк" <каталог парсера>` — числа только из JSON; значение в JSON с комментарием (json5).
- [ ] Идемпотентность: тест «двойной прогон одного фида» — число товаров не меняется.
- [ ] На проде: пробный прогон одного поставщика без записи в витрину — в логе число товаров фида и ноль ошибок; команда и вывод — в «Результат».
- [ ] Ключи не в git: `git grep -n -i "apikey\|api_key\|token" -- <каталог парсера>` — только имена настроек, без значений.

## Проверки

- [ ] `make check` (или `python scripts/dev.py check`) — зелёный вывод
- [ ] Self-review — чеклист «Перед сдачей» в [AGENTS.md](../AGENTS.md)
