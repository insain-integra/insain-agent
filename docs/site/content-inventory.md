## Плагин insainParse

Путь: `/var/www/insain.ru/wp-content/plugins/insainParse`. В списке плагинов: имя `insainParse`, заголовок InsainParser, статус active, версия пустая. Описание в шапке: «Загрузка и обновление остатков». Это не копия из git этого репозитория, на сервере только каталог плагина.

Что делает: качает каталог, товары и остатки поставщика, показывает в админке дерево групп и связи с рубриками WooCommerce, ставит задачи на обновление остатков и связей. Пункт меню админки «InsainParser» (`manage_options`), экран `includes/view/mfp-first-acp-page.php`.

Поставщики в коде и в интерфейсе (в селекте написано Happygifs):

| Ключ | Класс | Данные на диске | Товары на сайте |
|---|---|---|---|
| `project` | `LoadFileProjectService` | `data/Project/files/`: каталог, товары (12.04.2022), остатки (01.01.2023), фильтры | 694 + вариации, SKU `prg` |
| `happy` | `LoadFileHappyService` | `data/HappyGifts/files/`: каталог 204 узла и 1 805 товаров (09.04.2022), остатки (01.01.2023) | нет |
| `oasis` | `LoadFileOasisService` | каталога `data/Oasis` нет; сервис ходит за каталогом и товарами по HTTP с ключом из настроек | нет |

Ключ Oasis и URL лежат в `settings/url_files_download.json`. В этот файл они не копировались.

Запуск. Рабочий вход — AJAX `POST /wp-admin/admin-ajax.php?action=post_request` (`includes/script/xhr.js` → `handler_post`). Кнопки экрана: «Обновить остатки» и «Обновить связи» создают задачу (`new_task`) по отмеченным поставщикам; «Запустить Крон» / «Остановить» вызывают `set_setting_time_cron_stock` и `stop_cron_stock`. Те пишут `settings/settime.json` и строку задачи (`use_order=1`), а не событие WP-Cron. В `settime.json` записано желание: остатки в 10:00, полный каталог в 08:05, период `oneDay`.

`wp cron event list` событий `update_stock_cron` и `check_task` не содержит. `wp_schedule_event` для `update_stock_cron` есть только в `ServiceWorkCron::start_cron_for_update_stock`, и этот метод ниоткуда не вызывается. Функция `update_stock` в `request_handler_post.php` закомментирована. Хуки `wp_ajax_load_file` → `file_load`, `wp_ajax_parse_product` → `parse_product` и `check_task` → `worker_start` зарегистрированы, самих функций в каталоге плагина нет. Crontab пользователя `agent` пуст. `/etc/cron.d/php` — штатная чистка PHP-сессий, не парсер.

Итог: сейчас парсер запускается только вручную из админки InsainParser. Расписание в JSON лежит, в планировщике WordPress его нет. Плагин в этой сессии не запускался и не отключался. На деактивации висит `deleteTabel`: выключение плагина удаляет его таблицы.
