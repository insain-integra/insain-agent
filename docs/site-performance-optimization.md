# Оптимизация быстродействия сайта (test.insain.ru)

Живой журнал работ: **базовые замеры → безопасные шаги → новые замеры после каждого этапа**.

План составлен для тестового сайта `test.insain.ru`, который должен заменить основной `insain.ru`. Поэтому приоритет — **не максимальный балл PageSpeed любой ценой**, а предсказуемые изменения, которые не ломают WordPress, WooCommerce, формы, геотаргетинг и калькуляторы.

- [wordpress-integration.md](wordpress-integration.md) — миграция калькуляторов с `/icalc/` на API

## Как мерить (одинаково каждый раз)

### PageSpeed Insights (лабораторный ориентир)

| Параметр | Значение |
|----------|----------|
| URL теста (главная) | `http://test.insain.ru/` |
| URL теста (калькулятор, опционально) | `http://test.insain.ru/catalog/kalkulyator-pazlov/` |
| Режим | **Мобильные устройства** |
| Инструмент | [PageSpeed Insights](https://pagespeed.web.dev/) |
| Ссылка на отчёт | [архив от 2026-05-24](https://pagespeed.web.dev/analysis/http-test-insain-ru/nf26zb4nra?hl=ru&form_factor=mobile) |

После каждого этапа: новый прогон → вставить ссылку на отчёт в таблицу этапа → скопировать **LCP, FCP, TBT, CLS, Speed Index** (и при желании общий балл Performance).

### Обязательные дополнительные проверки

- Chrome DevTools → Network: есть ли `Content-Encoding: gzip` у `.css`/`.js`, есть ли `Cache-Control` у картинок из `uploads/`
- Время ответа сервера: заголовки ответа HTML (TTFB в Network)
- Проверка из России: открыть сайт с обычного российского провайдера без VPN и посмотреть, не зависает ли загрузка на Google Fonts, reCAPTCHA, Jetpack, внешней аналитике
- Проверка будущего боевого режима: перед переключением домена повторить замеры уже на `https://insain.ru/`

**Важно:** сравнивайте один и тот же URL. Главная и страница калькулятора дают разные цифры. PageSpeed Insights выполняется из инфраструктуры Google, поэтому для пользователей из России реальные задержки внешних ресурсов могут отличаться.

## Принципы безопасной оптимизации

Этот план оставляет только изменения с низким риском поломки сайта. Всё, что часто ломает Porto, WPBakery, WooCommerce или формы, вынесено в список «не включать без отдельного теста».

### Разрешённые безопасные изменения

| Изменение | Почему безопасно |
|-----------|------------------|
| HTTPS на тестовом домене с проверкой `nginx -t` | приближает тест к будущему `insain.ru`, не меняет логику WordPress |
| gzip для текстовых файлов | меняет только транспортный размер ответа, не меняет содержимое |
| `Cache-Control` для статических файлов | не меняет HTML и PHP-логику; для `uploads` используется умеренный срок без `immutable` |
| Локальная раздача шрифтов вместо Google Fonts | убирает зависимость от внешних доменов; визуально проверяется вручную |
| Оптимизация LCP-картинки без lazy-load на первом экране | уменьшает вес главного изображения, не меняет логику сайта |
| Удаление legacy `/icalc/` только после успешной проверки bridge/API на конкретной форме | изменение делается по одному калькулятору и проверяется вручную |

### Не включать без отдельного ручного теста

| Опция | Почему исключена из базового плана |
|-------|------------------------------------|
| Combine CSS / Combine JS | часто ломает порядок стилей и скриптов Porto/WPBakery/WooCommerce |
| Delay JS / агрессивный defer JS | может сломать мобильное меню, ez Form Calculator, фильтры, корзину |
| Автоматический Critical CSS / UCSS | может скрыть стили первого экрана или сломать адаптив |
| HTML Page Cache через LiteSpeed Cache на nginx без проверки | LSCache page cache рассчитан на LiteSpeed/OpenLiteSpeed; на nginx нельзя считать его гарантированно рабочим |
| Долгий `immutable` для всех `uploads` | если файл заменят с тем же именем, пользователи могут долго видеть старое изображение |
| Отключение reCAPTCHA полностью | может улучшить скорость, но ухудшить защиту форм от спама |

## Этап 1. HTTPS на тестовом домене

**Зачем (для новичка):** тестовый сайт должен максимально походить на будущий боевой `insain.ru`. Если оптимизировать `http://test.insain.ru`, а потом включить HTTPS, могут появиться новые редиректы, mixed content, другие cookies и отличающиеся замеры.

**Безопасный вариант:** включить HTTPS на `test.insain.ru` через Let's Encrypt / certbot, предварительно сохранив копию nginx-конфига и проверяя синтаксис через `nginx -t`.

**Что сделать:**

1. Сохранить копию текущего nginx-конфига.
2. Выпустить сертификат для `test.insain.ru`.
3. В WordPress на тесте проверить `siteurl` и `home`: они должны соответствовать выбранному протоколу.
4. Проверить, что нет mixed content (ресурсов `http://` на HTTPS-странице).
5. Прогнать PSI уже для `https://test.insain.ru/`.

**Риски:** ошибка в nginx-конфиге или mixed content. Откат — вернуть копию конфига и перезагрузить nginx после `nginx -t`.

## Этап 2. nginx: gzip и безопасный кеш статики

**Зачем (для новичка):** браузер скачивает меньше байт (gzip) и при повторном визите не качает заново картинки/CSS/JS (долгий `Cache-Control`). Это бьёт по предупреждениям PSI про кеш (~2 MiB) и ускоряет загрузку CSS из отчёта «блокирующие запросы».

**Где:** VDS, файл вида `/etc/nginx/sites-available/insain.ru` (ориентир — [infra/nginx-wp.conf](../infra/nginx-wp.conf), нужно **дополнить**, не заменить слепо).

### Что сделать безопасно

1. Включить `gzip` для текстовых типов: `text/html`, `text/css`, `application/javascript`, `application/json`, `image/svg+xml`.
2. Для версионированной статики WordPress (`wp-includes`, `wp-content/themes`, `wp-content/plugins`) задать долгий кеш: до 1 года, можно `immutable`.
3. Для `wp-content/uploads` задать умеренный кеш: 30–90 дней, **без** `immutable`, чтобы замена изображений с тем же именем не зависала у пользователей слишком долго.
4. Не кешировать HTML через nginx на этом этапе.
5. `sudo nginx -t && sudo systemctl reload nginx`.
6. Проверить в DevTools: у `.css` есть `Content-Encoding: gzip`; у файла из `uploads/` — `Cache-Control` с `max-age`.

**Риски:** ошибка в синтаксисе nginx — сайт не откроется; всегда сначала `nginx -t`.

- [ ] gzip включён и проверен на `.css` / `.js`
- [ ] долгий кеш включён для `themes`, `plugins`, `wp-includes`

- [ ] HTML, корзина и checkout не закешированы nginx
- [ ] сайт открывается, каталог и корзина работают

## Этап 3. Внешние ресурсы и доступность из России

**Зачем:** сайт находится на хостинге в России и рассчитан на российских пользователей. Внешние ресурсы Google/Automattic/других зарубежных сервисов могут быть медленными, нестабильными или недоступными у части пользователей. PSI может показывать одну картину, а реальный пользователь в РФ — другую.

### Что сделать безопасно

| Ресурс | Безопасное действие |
|--------|---------------------|
| Google Fonts (`fonts.googleapis.com`, `fonts.gstatic.com`) | скачать используемые шрифты и отдавать с `test.insain.ru`; добавить `font-display: swap` |
| Font Awesome / Porto fonts | оставить локальными, проверить кеш через nginx |
| Jetpack / `stats.wp.com` | если аналитика не нужна для теста и продакшена — отключить Jetpack Stats; если нужна — оставить, но не считать её критичной для первого экрана |
| reCAPTCHA | не отключать полностью; подключать только на страницах с формами, если плагин это позволяет безопасно |
| сторонние счётчики | оставить только необходимые; всё необязательное грузить после первого экрана или убрать |

**Не делать на этом этапе:** агрессивный `defer/delay` всех внешних скриптов. Это может сломать формы, капчу, корзину или геотаргетинг.

### Чек-лист 3

- [ ] Google Fonts не грузятся с внешних доменов на главной
- [ ] шрифты имеют `font-display: swap`
- [ ] reCAPTCHA не грузится на страницах без форм (если это можно сделать штатно)
- [ ] сайт проверен из России без VPN

## Этап 4. LCP-элемент (первый экран)

**Зачем:** при LCP **10,4 с** узкое место почти всегда одна большая картинка или тяжёлый слайдер.

### Безопасные действия

- найти LCP-элемент в PSI;
- сжать именно это изображение без изменения размеров блока;
- подготовить WebP/AVIF, но оставить оригинал как fallback;
- убедиться, что LCP-картинка **не lazy-load**;
- добавить `width` и `height` / `aspect-ratio`, если это обычный `<img>`;
- если это слайдер, сначала уменьшить вес первого слайда, а не отключать слайдер.

## Исключённые рискованные оптимизации

Эти пункты могут быть полезны позже, но не входят в безопасный план:

- LSCache Page Cache как основной HTML-кеш на nginx без доказательства, что он реально работает в текущем стеке;
- Combine CSS / Combine JS;
- Delay JS для всех скриптов;
- автоматический Critical CSS / UCSS;
- отключение jQuery, jQuery Migrate или WooCommerce-скриптов;
- отключение reCAPTCHA без замены антиспама;
- массовое отключение плагинов без карты страниц, где они используются.

Если понадобится дальнейшее ускорение после этапов 1–6, для этих пунктов нужно заводить отдельный план тестирования с быстрым откатом.
