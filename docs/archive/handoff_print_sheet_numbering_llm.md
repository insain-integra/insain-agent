# Handoff: галлюцинации при «добавь нумерацию» (листовая печать, print_sheet)

## Задача для внешней LLM

Проанализировать, **почему** Telegram-бот иногда показывает пользователю **выдуманные** цены/строки ответа при запросе нумерации к уже посчитанному заказу листовой печати, и предложить **устойчивое решение** (промпт, логика агента, схема API).

## Симптомы (репорт)

- После фраз вроде «добавь нумерацию» бот отвечает **без вызова** `calc_print_sheet` с реальными числами из API.
- В тексте могут появляться **несуществующие** детали (например, строка про «нумератор» в материалах), **неверная** share-ссылка (параметр `numbering=true` вместо канонического `option_numbering` в query API).

## Архитектура (кратко)

- **Одноступенчатый агент**: одна LLM с tools (`search_materials`, `calc_*`). Истина по цене — только **вызов калькулятора** (FastAPI `calc_service`).
- Калькулятор **листовой печати**: `calc_service/calculators/print_sheet.py`, slug `print_sheet`, tool `calc_print_sheet`.
- Постпечать (нумерация и др.) считается в коде по флагам **`option_numbering`**, **`option_barcode`**, **`option_variable_data`**, опционально скругление/пробивка/биговка. В JS-наследии также встречались алиасы `is_number`, `is_barcode`, … — в Python они учтены в `_print_sheet_extra_options`.

## Канонические имена параметров (важно для LLM и share URL)

- **Нумерация**: `option_numbering: boolean` (не `numbering`, не `isNumber` в URL — в API/tool_schema именно `option_numbering`).
- Аналогично: `option_barcode`, `option_variable_data`, `option_rounding`, `holes_per_item`, `crease_lines_per_item`.

## Цепочка в боте (`bot_service/agent.py`)

1. **`_try_forced_calc`**: если пользователь пишет короткое уточнение к **тому же** калькулятору и в контексте уже есть сохранённые параметры, агент **может** пересчитать на сервере **без** ответа модели с `tool_calls` (см. docstring у метода).
2. Условие запуска завязано на **`_user_message_suggests_recalc`**: сейчас распознаются в основном **тираж** (`N шт`), **цветность** (`4+4`, `1+0`, …), комбинации с «посчитай/пересчитай» + цифры/цветность.
3. Фразы вида **«добавь нумерацию»** **не** входят в этот паттерн → `forced calc` **не срабатывает**.
4. Если модель при этом возвращает **только текст** (без `tool_calls` с `calc_print_sheet`), пользователь видит **галлюцинированный** «расчёт».

## Гипотеза причины (для проверки)

1. **Нет серверного пересчёта** для запросов про опции постпечати (только LLM-текст).
2. **Нет явного запрета** в system prompt на выдумывание цифр при активной calc-сессии (или недостаточный акцент на обязательный `calc_print_sheet`).
3. Возможная **путаница имён** (`numbering` vs `option_numbering`) в тексте модели и в ссылках.

## Что уже пробовали (контекст)

- Расширение триггера forced recalc / слияние `option_*` из реплики пользователя с параметрами контекста — **обсуждалось и может быть откатано**; актуальное состояние смотреть по git и по приложенным исходникам `agent.py`.
