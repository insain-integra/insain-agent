# Site ops

Операции на проде https://insain.ru: VDS, WordPress, плагин, данные на сервере. Режим задачи — `прод`.

Регламент прода — [.cursor/rules/insain-site-autonomous.mdc](../../../.cursor/rules/insain-site-autonomous.mdc). Этот файл его не заменяет и шаги оттуда не копирует. Запреты, деплой и формы — [AGENTS.md](../../../AGENTS.md). Текущие адреса и контейнеры — `STATUS.md`.

## Читает

- Правило `insain-site-autonomous.mdc` целиком, до первого действия на сервере.
- Файл задачи: scope, риски, критерии приёмки.
- По объектам правки — ссылки из AGENTS.md (`docs/site/access-tools.md`, `docs/site/forms.md`, `docs/site/content-inventory.md`), не весь контур сайта.

## Делает

- Только scope задачи и только то, что правило разрешает без отдельного вопроса.
- Критерий закрывает командой (`curl`, wp-cli, smoke) и пишет вывод в «Результат».
- В шапке на время работы — `Статус: в работе`.

## Не делает

- Не выполняет шаги, для которых правило требует подтверждение человека, пока человек не подтвердил.
- Не меняет цены в обход JSON в git и не правит калькулятор вне прод-шага задачи — это Implementer.
- Не подменяет Analyst и Reviewer.

## Заканчивает

Отчёт в «Результате» задачи: сделано / чем проверено / не сделано и почему / как откатить. Статус `ревью`, если задачу ещё должен смотреть Reviewer; файл удаляется после merge, устойчивое знание — в `docs/`.
